# 第 29 课：I2C 读写 MPU6050

## 1. 本课到底在学什么

本课表面现象是：STM32 通过 I2C1 唤醒 MPU6050，并周期读取 `WHO_AM_I` 身份寄存器；如果读到 `0x68`，PC13 LED 快速闪烁，否则慢速闪烁。

真正要学的是：I2C 传感器通常不是“直接读数据”，而是先访问器件内部寄存器。你要先发送器件地址，再发送寄存器地址，然后读写寄存器内容。

本课链路是：

```text
PB6/PB7 I2C1
  -> MPU6050 地址 0x68
  -> 写 PWR_MGMT_1(0x6B) = 0x00 唤醒
  -> 读 WHO_AM_I(0x75)
  -> 返回值应为 0x68
  -> 根据 ID 控制 PC13 闪烁快慢
```

这节课不是完整姿态解算课，也没有读取加速度和陀螺仪数据。它先教你验证一个 I2C 传感器是否在线、地址是否正确、寄存器读写是否通。

## 2. 本课学习目标

学完本课，你应该能回答：

1. MPU6050 的 7 位地址 `0x68` 为什么在代码里写成 `0xD0/0xD1`？
2. `PWR_MGMT_1` 为什么上电后要写 `0x00`？
3. `WHO_AM_I` 为什么适合作为 I2C 通信自检寄存器？
4. 读 MPU6050 寄存器为什么需要“先写寄存器地址，再重复起始读数据”？
5. `HAL_I2C_Mem_Read()` 的 `I2C_MEMADD_SIZE_8BIT` 为什么不能乱选？
6. ID 读不到 `0x68` 时应该优先排查哪几层？
7. 本课 LED 快慢闪分别代表什么？

## 4. 实验硬件

- 开发板：STM32F103C8T6 BluePill
- 下载器：ST-Link
- 传感器：MPU6050 模块
- I2C 引脚：PB6 = SCL，PB7 = SDA
- LED：PC13

接线：

```text
MPU6050 VCC -> 3.3V
MPU6050 GND -> GND
MPU6050 SCL -> PB6
MPU6050 SDA -> PB7
```

多数 MPU6050 模块 AD0 接低电平时 7 位地址为 `0x68`。若 AD0 接高电平，地址会变为 `0x69`，代码中的地址也要相应修改。

## 5. 先建立一个最基本的脑图

```text
I2C1 初始化
  -> PB6/PB7 复用开漏
  -> 100kHz 标准模式

唤醒 MPU6050
  -> START
  -> 地址+写 0xD0
  -> 寄存器地址 0x6B
  -> 数据 0x00
  -> STOP

读取 WHO_AM_I
  -> START
  -> 地址+写 0xD0
  -> 寄存器地址 0x75
  -> RESTART
  -> 地址+读 0xD1
  -> 读 1 字节
  -> STOP

判断结果
  -> id == 0x68：快速闪烁
  -> id != 0x68：慢速闪烁
```

这节课的关键是把“传感器内部寄存器地址”和“I2C 器件地址”分清楚。`0x68` 是器件地址/身份值，`0x75` 是 WHO_AM_I 寄存器地址，`0x6B` 是电源管理寄存器地址。

## 6. 核心名词解释

### 6.1 已学名词速查

以下概念在 26 课（I2C 基础）和 27 课（软件 I2C）中已经详细讲过。这里只给一句话提醒，不重复展开。

| 名词                       | 一句话提醒                                                                                 |
| -------------------------- | ------------------------------------------------------------------------------------------ |
| `I2C1`                   | STM32 的 I2C 外设，PB6=SCL、PB7=SDA，挂在 APB1（PCLK1=36MHz）                              |
| `复用开漏`               | I2C 引脚必须配成开漏（不是推挽），否则多设备共享总线时会短路烧 IO                          |
| `上拉电阻`               | 开漏输出只能拉低不能推高，高电平靠外部 4.7kΩ 上拉到 3.3V 提供                             |
| `7 位地址左移`           | I2C 线上地址字节 = 7 位地址 << 1\| R/W，`0x68` 左移后写地址=`0xD0`、读地址=`0xD1`    |
| `START`                  | SCL 高时 SDA 从高→低，主机产生，标志一次传输开始                                          |
| `STOP`                   | SCL 高时 SDA 从低→高，主机产生，标志一次传输结束                                          |
| `ACK / NACK`             | 每字节后接收方拉低 SDA（ACK）或不拉低（NACK），主机据此判断从机是否响应                    |
| `重复起始 (RESTART)`     | 不先发 STOP 就直接再发 START，用于写完寄存器地址后切到读方向，不释放总线                   |
| `ADDR 清除`              | 地址阶段完成后必须先读 SR1 再读 SR2，否则 ADDR 标志不清、状态机卡住                        |
| `TXE / BTF / RXNE`       | TXE=发送寄存器空可写下一字节，BTF=字节传输完成，RXNE=接收寄存器有数据可读`                 |
| `CCR / TRISE / FREQ`     | CCR=时钟分频（本课 180→100kHz），TRISE=上升时间（本课 37），FREQ=APB1 频率 MHz（本课 36） |
| `HAL_I2C_Mem_Write/Read` | HAL 封装了"器件地址+寄存器地址+数据"的读写流程，26 课 EEPROM 已用过                        |

### 6.2 MPU6050 是什么

MPU6050 是一颗**6 轴惯性传感器**，内部包含三轴加速度计和三轴陀螺仪。

**加速度计的物理原理**：芯片内部有 MEMS 微机械结构——微小的硅质质量块通过弹性梁悬挂着。当芯片加速时，惯性使质量块相对芯片产生位移，位移量通过电容极板间距变化转换成电压，再经内部 ADC 变成数字量。静止时 Z 轴读到的不是 0，而是约 +1g（重力加速度），因为加速度计测的是"视加速度"——包括重力。这是正常现象，不是芯片坏了。

**陀螺仪的物理原理**：芯片内部有振动质量块，利用科里奥利效应——旋转坐标系中运动的物体受到垂直于运动方向的力。芯片测量这个力的大小，就知道绕轴转动的角速度。单位是 °/s（度每秒）。

MPU6050 内部有一张**寄存器表**（register map），每个寄存器有一个 8 位地址，存着配置值或测量数据。STM32 通过 I2C 访问这些寄存器。

**本课为什么需要它**：它是第一个 I2C 传感器案例。和 26 课的 EEPROM 不同，EEPROM 是存储器件，MPU6050 是传感器件——EEPROM 的"内部地址"是存储单元编号，MPU6050 的"内部地址"是功能寄存器编号。概念不同，但 I2C 访问流程相同。

**配错会怎样**：模块没供电、地址不对、AD0 电平不匹配、没上拉电阻 → I2C 通信失败，读不到 `0x68`。

### 6.3 器件地址 vs 寄存器地址

这是本课最容易混淆的概念，必须彻底分清。

**I2C 器件地址**（`0x68`）是 MPU6050 在 I2C 总线上的"身份证号"。主机发 START 后第一个字节就是器件地址，总线上所有从机都收到，只有地址匹配的那颗芯片应答 ACK。好比快递员在楼下喊"张三！"，只有张三回头。

**寄存器地址**（`0x6B`、`0x75`）是 MPU6050 芯片内部的"功能编号"。器件地址匹配后，MPU6050 已经"在线"了，但还不知道你要它干什么。接下来发送的字节是寄存器地址，告诉它"我要访问你的电源管理寄存器"或"我要读你的身份寄存器"。好比进了张三的家门，还要说"去你卧室"还是"去你厨房"。

**为什么要左移**：I2C 协议规定地址字节 = 7位地址 << 1 | R/W。这不是 MPU6050 的特殊要求，而是所有 I2C 器件的统一规则。`0x68 << 1 | 0 = 0xD0`（写），`0x68 << 1 | 1 = 0xD1`（读）。寄存器版定义 `MPU_ADDR_W 0xD0` 和 `MPU_ADDR_R 0xD1`。HAL 版传入 `MPU_ADDR 0xD0`，HAL 内部根据读写方向自动处理最低位。

**为什么必须区分**：在 I2C 总线上，器件地址决定"哪个芯片理你"，寄存器地址决定"芯片内部哪个功能被访问"。把 `0x75` 当器件地址发，总线上没有地址 `0x75` 的器件，没人应答 ACK，通信卡死。

**比喻**：I2C 总线像一条街，每个器件是一栋楼，器件地址是门牌号。寄存器地址是楼里的房间号。先找到楼，再进房间。本课的 `0x68` 既是门牌号（器件地址）也是 WHO_AM_I 房间里的内容（返回值），但 `0x75` 才是 WHO_AM_I 的房间号（寄存器地址）。三个概念不要搞混。

---

### 6.4 PWR_MGMT_1

`PWR_MGMT_1` 是 MPU6050 的**电源管理寄存器 1**，寄存器地址 `0x6B`。

**为什么芯片要有这个寄存器**：MPU6050 内部有加速度计、陀螺仪、ADC、数字处理器等多个模块，全速运行功耗约 3.9mA。电池供电的设备（无人机、手环）需要省电，所以芯片设计上电后默认让部分模块休眠，等主机明确说"醒醒，干活了"再全速运行。

**本课写 `0x00` 的原因**：`PWR_MGMT_1` 的 bit6（SLEEP）控制睡眠。上电复位后 SLEEP=1，芯片在睡觉。写 `0x00` 把所有位清零 → SLEEP=0 → 芯片唤醒。不写 `0x00` 的话，`WHO_AM_I` 也许还能读到（I2C 接口是独立供电的），但加速度和陀螺仪的数据寄存器不会更新——测量模块还在睡觉。

**配错会怎样**：忘了写 `0x00` → 后续读取加速度/陀螺仪数据始终是同一个值（上电默认值），看起来像"通信成功了但数据不变"。这是新手最容易踩的坑——能读到 WHO_AM_I 就以为一切正常，其实传感器还在睡眠。

---

### 6.5 WHO_AM_I

`WHO_AM_I` 是 MPU6050 的**身份寄存器**，寄存器地址 `0x75`，正常返回值 `0x68`。

**为什么芯片要有这个寄存器**：I2C 总线上可能挂多个不同型号的传感器（MPU6050、BMP280、HMC5883 等）。主机的驱动程序需要确认"我连接的是不是我以为的那颗芯片"。WHO_AM_I 就是芯片的"身份证"号——硬编码在芯片内部，只读，永远不会变。读到 `0x68` 说明这不是 MPU6050 的某个变种，而是标准 MPU6050。

**为什么适合做通信自检**：WHO_AM_I 不需要任何配置，只要芯片上电、I2C 通了，就能读到。且返回值是已知固定值 `0x68`，方便比对。读不到 `0x68` 时，问题一定在供电、接线、地址、I2C 读流程这四层之一。

**配错会怎样**：读到 `0x00` 或 `0xFF` → SDA 一直被拉低或一直被拉高，通信根本没发生。读到随机值 → 时序错乱，读到了错误的寄存器。

---

### 6.6 I2C_MEMADD_SIZE_8BIT

HAL 的 `HAL_I2C_Mem_Write()` 和 `HAL_I2C_Mem_Read()` 的第 4 个参数，告诉 HAL "内部寄存器地址是几个字节"。

**为什么需要这个参数**：不同 I2C 器件的寄存器地址长度不同。MPU6050 寄存器地址是 8 位（1 字节），范围 0x00~0x7F。但有些器件（如大容量 EEPROM AT24C256）内存地址是 16 位（2 字节），需要发两个字节才能选中内部单元。HAL 不知道你接的是什么器件，所以你必须告诉它。

`I2C_MEMADD_SIZE_8BIT` 的值是 `1`：HAL 在器件地址之后发送 1 个字节作为寄存器地址。

**配错会怎样**：误用 `I2C_MEMADD_SIZE_16BIT`（值为 2），HAL 多发一个字节，MPU6050 把第二个字节当数据，导致寄存器地址偏移或数据写入错误寄存器。

---

### 6.7 单字节读的 ACK/STOP 时序

本课只读 1 个字节（WHO_AM_I），需要理解**为什么**单字节读必须提前关 ACK。

**I2C 读的规则**：主机每收到一个字节后，第 9 个时钟发 ACK（SDA 拉低）或 NACK（SDA 释放）。ACK 的意思是"再来一个字节"，NACK 的意思是"够了，别发了"。

**本课只读 1 个字节**：主机必须在收到这个字节时发 NACK，告诉 MPU6050 "这是最后一个"。但 STM32F103 的 I2C 外设有一个坑：ACK 位必须在地址阶段完成**之前**配置好，否则外设来不及在正确时机发出 NACK。

**所以代码顺序是**：先清 ACK → 再发重复起始和读地址 → 地址阶段完成后立即设 STOP → 等 RXNE → 读 DR → 恢复 ACK。这个顺序不能乱。

**配错会怎样**：ACK 关太晚 → MPU6050 收到 ACK，以为主机还要继续读，多发出一个字节，而主机已发 STOP，总线状态混乱。STOP 太早 → 从机还没发完数据就被掐断。STOP 太晚 → 总线保持 BUSY，下一次通信卡住。

---

### 6.8 PC13 快慢闪

本课的现象输出，用 LED 闪烁频率表示通信状态。

**寄存器版**：`delay_cycles(720000)` 约 10ms，`delay_cycles(3600000)` 约 50ms。每个循环翻转一次 LED，快闪周期约 20ms，慢闪周期约 100ms。

**HAL 版**：`HAL_Delay(100)` 快闪周期约 200ms（亮 100ms 灭 100ms），`HAL_Delay(500)` 慢闪周期约 1000ms（亮 500ms 灭 500ms）。

**为什么用不同延时**：不是为了"好看"，而是让你不用串口就能判断通信状态。ID 正确 → 快闪，说明 I2C 链路通了。ID 错误 → 慢闪，说明代码在跑但通信有问题。LED 完全不闪 → 程序可能卡在 I2C 等待处。

### 7.2 本课新增：`mpu_write_register()` —— 写传感器寄存器

```c
static void mpu_write_register(uint8_t reg, uint8_t value)
{
    i2c_start_and_address(MPU_ADDR_W);  /* 选中 MPU6050，写方向 */
    i2c_write_byte(reg);                /* 告诉它：我要写寄存器 reg */
    i2c_write_byte(value);              /* 写入数据 */
    while ((I2C1->SR1 & I2C_SR1_BTF) == 0U) { }  /* 等字节传输完成 */
    I2C1->CR1 |= I2C_CR1_STOP;          /* 传输结束 */
}
```

**和 26 课 EEPROM 写的区别**：26 课写 EEPROM 时，`i2c_write_byte(reg)` 发的是 EEPROM 存储单元地址。本课发的是 MPU6050 功能寄存器地址。I2C 流程完全相同，但"地址"的语义不同——一个是存储位置，一个是功能选择。

**本课用它写 `0x6B=0x00`**：唤醒 MPU6050。`0x6B` 是 PWR_MGMT_1 寄存器地址，`0x00` 清掉 SLEEP bit。

**为什么等 BTF 而不是 TXE**：写最后一个字节时，TXE 在数据从 DR 移到移位寄存器后就置位了，但此时数据可能还在 SDA 线上传输。BTF 要等到移位寄存器也空了、SCL 上最后一个时钟也发完了才置位。在 BTF 之后发 STOP 才能保证数据完整传输。

---

### 7.3 本课新增：`mpu_read_register()` —— 读传感器寄存器（第一段：写寄存器地址）

```c
i2c_start_and_address(MPU_ADDR_W);   /* 选中 MPU6050，写方向 */
i2c_write_byte(reg);                 /* 发寄存器地址 */
while ((I2C1->SR1 & I2C_SR1_BTF) == 0U) { }
```

**为什么读操作也要先用写方向**：MPU6050 内部有几十个寄存器，你不知道它当前指向哪个。必须先告诉它"我要读寄存器 `reg`"，它才能把正确的数据准备好。写寄存器地址属于写操作，所以用写方向地址 `0xD0`。

**为什么不在这里发 STOP**：如果 STOP，MPU6050 的内部地址指针会复位。后面用重复起始（RESTART）切到读方向，总线不释放，地址指针保持，MPU6050 才知道你要读刚才指定的那个寄存器。

---

### 7.4 本课新增：`mpu_read_register()` —— 读传感器寄存器（第二段：重复起始 + 读数据）

```c
I2C1->CR1 &= ~I2C_CR1_ACK;          /* ① 先关 ACK */
i2c_start_and_address(MPU_ADDR_R);   /* ② 重复起始，读方向 */
I2C1->CR1 |= I2C_CR1_STOP;           /* ③ 立刻设 STOP */
while ((I2C1->SR1 & I2C_SR1_RXNE) == 0U) { }  /* ④ 等数据 */
value = (uint8_t)I2C1->DR;           /* ⑤ 读数据 */
I2C1->CR1 |= I2C_CR1_ACK;            /* ⑥ 恢复 ACK */
```

**为什么这 6 步的顺序不能乱**：

1. **先关 ACK**：F103 的 I2C 外设用 ACK 位控制第 9 个时钟发 ACK 还是 NACK。必须在地址阶段完成前配好，否则外设来不及在正确时机发 NACK。
2. **重复起始 + 读地址**：不 STOP 直接再 START，切到读方向 `0xD1`。从机知道你要读数据。
3. **立刻设 STOP**：告诉外设"收到数据后自动发 STOP"。F103 需要在收到数据前就知道要发 STOP。
4. **等 RXNE**：数据寄存器收到数据。
5. **读 DR**：取出数据。
6. **恢复 ACK**：为下次通信恢复默认状态。

**如果顺序错了**：

- 先读地址再关 ACK → 外设已发出 ACK，MPU6050 以为还要继续发，多发出一个字节，总线乱
- STOP 设太晚 → 外设不知道要 STOP，总线保持 BUSY
- 读完不恢复 ACK → 下次通信永远发 NACK

---

### 7.5 本课新增：`main()` 中的唤醒和 ID 读取

```c
mpu_write_register(0x6BU, 0x00U);   /* 唤醒 MPU6050 */

while (1) {
    uint8_t id = mpu_read_register(0x75U);  /* 读 WHO_AM_I */
    pc13_toggle();
    if (id == 0x68U) {
        delay_cycles(720000U);    /* 快闪：约 10ms 延时 */
    } else {
        delay_cycles(3600000U);   /* 慢闪：约 50ms 延时 */
    }
}
```

**唤醒只做一次**：`mpu_write_register` 在 while(1) 外面，因为 MPU6050 唤醒后不会自动再睡。如果不唤醒，WHO_AM_I 仍可读，但后续加速度数据不会更新。

**ID 读取在循环里**：每次循环读一次 WHO_AM_I，根据结果选延时。如果某次读失败（比如 MPU6050 掉线），`id` 会保持上一次的值——这是寄存器版的一个局限，因为没有错误处理，读失败不会改变 `id`。

## 8. HAL 版代码逐步讲解

### 8.1 已学步骤（快速过）

| 步骤           | HAL API                                             | 对应寄存器版                     |
| -------------- | --------------------------------------------------- | -------------------------------- |
| 系统时钟 72MHz | `HAL_RCC_OscConfig()` + `HAL_RCC_ClockConfig()` | 手动写 RCC->CR、CFGR、FLASH->ACR |
| PC13 LED 推挽  | `HAL_GPIO_Init(GPIOC, GPIO_PIN_13, PP)`           | 手动写 GPIOC->CRH                |
| SysTick 1ms    | `HAL_Init()` 内部调用 `HAL_InitTick()`          | 手动写 SysTick->LOAD、CTRL       |
| I2C1 GPIO 开漏 | `HAL_GPIO_Init(GPIOB, PB6\|PB7, AF_OD)`            | 手动写 GPIOB->CRL                |
| I2C1 配置      | `HAL_I2C_Init(&hi2c1)`                            | 手动写 CR2/CCR/TRISE/CR1         |

**HAL I2C1 配置字段 → 寄存器映射**：

| HAL 字段                | 值                          | 对应寄存器     | 对应位                                  |
| ----------------------- | --------------------------- | -------------- | --------------------------------------- |
| `hi2c1.Instance`      | `I2C1`                    | -              | 选择 I2C1 外设基地址                    |
| `Init.ClockSpeed`     | `100000`                  | `I2C1->CCR`  | HAL 按 PCLK1=36MHz 自动算出 CCR=180     |
| `Init.DutyCycle`      | `I2C_DUTYCYCLE_2`         | `I2C1->CCR`  | DUTY=0（标准模式 t_low/t_high=1:1）     |
| `Init.OwnAddress1`    | `0`                       | `I2C1->OAR1` | 本课是主机模式，自身地址不重要          |
| `Init.AddressingMode` | `I2C_ADDRESSINGMODE_7BIT` | `I2C1->CR2`  | 无直接对应，影响 HAL 打包地址字节的方式 |
| `Init.NoStretchMode`  | `I2C_NOSTRETCH_DISABLE`   | `I2C1->CR1`  | NOSTRETCH=0（允许从机拉低 SCL 延时）    |

---

### 8.2 本课新增：`HAL_I2C_Mem_Write()` —— 唤醒 MPU6050

```c
uint8_t wake_value = 0U;
if (HAL_I2C_Mem_Write(&hi2c1,
                      MPU_ADDR,                 /* 器件地址 0xD0 */
                      0x6BU,                    /* 内部寄存器地址 PWR_MGMT_1 */
                      I2C_MEMADD_SIZE_8BIT,     /* 寄存器地址 1 字节 */
                      &wake_value,              /* 要写入的数据 0x00 */
                      1U,                       /* 写入 1 字节 */
                      100U) != HAL_OK) {        /* 超时 100ms */
    error_handler();
}
```

**HAL 底层做了什么事**（对应寄存器版 `mpu_write_register`）：

1. `I2C1->CR1 |= I2C_CR1_START` → 等 SB
2. `I2C1->DR = 0xD0` → 等 ADDR → 读 SR1+SR2 清标志
3. `I2C1->DR = 0x6B` → 等 TXE（发寄存器地址）
4. `I2C1->DR = 0x00` → 等 BTF（发数据）
5. `I2C1->CR1 |= I2C_CR1_STOP`

**参数含义**：

- `MPU_ADDR`（`0xD0`）：7 位地址 `0x68` 左移一位，HAL F1 需要左移后的地址
- `0x6B`：MPU6050 内部寄存器地址，不是 I2C 器件地址
- `I2C_MEMADD_SIZE_8BIT`（值为 1）：寄存器地址 1 字节。误用 2 字节会多发一个字节
- `100U`：超时 100ms。如果 100ms 内没完成，返回 `HAL_TIMEOUT`

---

### 8.3 本课新增：`HAL_I2C_Mem_Read()` —— 读取 WHO_AM_I

```c
if (HAL_I2C_Mem_Read(&hi2c1,
                     MPU_ADDR,                 /* 器件地址 0xD0 */
                     0x75U,                    /* 内部寄存器地址 WHO_AM_I */
                     I2C_MEMADD_SIZE_8BIT,     /* 寄存器地址 1 字节 */
                     &id,                      /* 读到的数据存这里 */
                     1U,                       /* 读取 1 字节 */
                     100U) != HAL_OK) {        /* 超时 100ms */
    error_handler();
}
```

**HAL 底层做了什么事**（对应寄存器版 `mpu_read_register`）：

1. START → 发 `0xD0` → 等 ADDR
2. 发 `0x75`（寄存器地址）→ 等 BTF
3. 重复起始 → 发 `0xD1`（读方向）→ 等 ADDR
4. 关 ACK、设 STOP → 等 RXNE → 读 DR

**HAL 的一个细节**：`MPU_ADDR` 是 `0xD0`（写地址），但 HAL 内部读取时会自动把最低位翻成 1（变成 `0xD1`），所以不需要像寄存器版那样分别定义 `MPU_ADDR_W` 和 `MPU_ADDR_R`。HAL 根据你是调用 `Mem_Write` 还是 `Mem_Read` 自动处理 R/W 位。

---

### 8.4 本课新增：`error_handler()` —— 通信失败处理

```c
static void error_handler(void)
{
    __disable_irq();
    while (1) { }
}
```

**为什么需要这个函数**：如果 `HAL_I2C_Mem_Write/Read` 返回非 `HAL_OK`，说明 I2C 通信失败了。此时继续运行可能读到错误数据，不如停下来让开发者发现问题。`__disable_irq()` 关闭全局中断，然后死循环，LED 保持进入时的状态——这本身就是一个可见信号：LED 不闪了 = 出问题了。

**和寄存器版的区别**：寄存器版没有错误处理，读失败时 `id` 保持上一次的值，LED 会继续按上一次的结果闪烁。这可能导致"明明 MPU6050 掉线了，LED 还在快闪"的误导。

## 9. 两个版本真正应该怎么学

寄存器版重点看 I2C 单字节寄存器读写的底层顺序；HAL 版重点看 `HAL_I2C_Mem_*` 如何把“器件地址、寄存器地址、数据缓冲区”组合起来。

本课要建立传感器访问模型：

```text
器件地址选中模块
寄存器地址选中模块内部功能
数据字节读写这个功能的状态或配置
```

## 10. 检验问题清单

### 10.1 `0x68` 和 `0xD0` 是什么关系？

**答**：`0x68` 是 MPU6050 的 7 位地址，`0xD0` 是它左移一位并加写位后的地址字节。

### 10.2 `WHO_AM_I` 为什么读到 `0x68`？

**答**：MPU6050 的身份寄存器设计为返回器件身份值。读到 `0x68` 说明地址、接线和寄存器读流程基本正确。

### 10.3 为什么要写 `PWR_MGMT_1=0x00`？

**答**：MPU6050 上电后常处于睡眠状态，写 `0x00` 用于唤醒传感器，为后续正常采样做准备。

### 10.4 读寄存器为什么先用写方向？

**答**：因为要先告诉 MPU6050 要读哪个内部寄存器。发送寄存器地址属于写方向，随后再重复起始切到读方向取数据。

### 10.5 `I2C_MEMADD_SIZE_8BIT` 控制什么？

**答**：它控制 HAL 发送几个字节作为内部寄存器地址。MPU6050 寄存器地址是 8 位，所以应选择 8 位。

### 10.6 LED 慢闪说明什么？

**答**：说明当前读到的 ID 不是 `0x68`。可能是模块未响应、地址错、读流程错，也可能是读到了错误值。

### 10.7 如果 AD0 接高要改哪里？

**答**：7 位地址从 `0x68` 变成 `0x69`。寄存器版写地址应改为 `0xD2`、读地址改为 `0xD3`；HAL 版地址改为 `0xD2`。

### 10.8 HAL 版为什么建议检查返回值？

**答**：因为返回值能区分 I2C 调用是否成功。否则 `id` 可能保持旧值或默认值，LED 现象会误导排查。

### 10.9 忘了写 `PWR_MGMT_1=0x00` 会怎样？

**答**：WHO_AM_I 可能仍能读到 `0x68`（I2C 接口独立供电），但后续读取加速度/陀螺仪数据时，数据寄存器始终是上电默认值，不会更新。看起来像"通信成功了但数据不变"，排查时容易误判为 I2C 没问题。

### 10.10 单字节读时忘了关 ACK 会怎样？

**答**：MPU6050 收到 ACK 后以为主机还要继续读，会多发出一个字节。但主机已经发了 STOP，多出来的字节没人读，总线状态可能混乱。轻则读到多余数据，重则下一次 I2C 通信时 BUSY 标志不释放，后续通信全部卡死。

### 10.11 HAL 的 `I2C_MEMADD_SIZE_8BIT` 对应寄存器版的哪一步？

**答**：对应寄存器版 `mpu_write_register()` 或 `mpu_read_register()` 中 `i2c_write_byte(reg)` 这一步。HAL 根据这个参数决定发几个字节作为内部寄存器地址。寄存器版手动发 1 个字节，HAL 版通过参数告诉 HAL 发 1 个字节。

## 11. 工程实现步骤

### 11.1 需求分析

本课只做 MPU6050 在线检测和唤醒，不做姿态角计算。先确认 I2C 寄存器读写可靠，后续读取传感器数据才有意义。

### 11.2 硬件核查

确认 MPU6050 供电、GND、PB6/PB7 接线、模块上拉和 AD0 电平。若模块是 5V 供电板，要确认 I2C 电平对 STM32 安全。

### 11.3 寄存器路线

配置 I2C1 后，先写 `0x6B=0x00`，再读 `0x75`。重点观察地址阶段 ACK、寄存器地址写入、重复起始和 RXNE。

### 11.4 HAL 路线

配置 `hi2c1` 后，用 `HAL_I2C_Mem_Write()` 写配置寄存器，用 `HAL_I2C_Mem_Read()` 读身份寄存器。建议补返回值判断。

### 11.5 工程思维

调传感器时先读 WHO_AM_I，不要一上来读数据寄存器。身份寄存器稳定、简单，是区分“通信不通”和“数据处理不对”的第一道门。

传感器调试应该分阶段：第一阶段只验证供电、地址、ACK；第二阶段读 WHO_AM_I；第三阶段写配置寄存器并读回确认；第四阶段再读数据寄存器。直接从姿态数据开始，会把硬件连接、I2C 协议、寄存器配置、数据换算全混在一起。

本课选择 WHO_AM_I 正是为了建立这个工程节奏。读到 `0x68` 只能证明基本通信和身份正确，不代表量程、采样率、滤波、坐标轴方向都配置好了。它是起点，不是完整驱动终点。

### 11.6 常见工程陷阱

地址左移、AD0 电平、寄存器地址长度、上拉电阻、模块供电最容易出错。不要把 `0x75` 当 I2C 地址，它只是 MPU6050 内部寄存器地址。

## 12. 运行现象

**通信正常时（ID 读到 `0x68`）**：

- 寄存器版：PC13 LED 以约 50Hz 频率快速闪烁（亮约 10ms、灭约 10ms），肉眼看起来像"微微发亮"或"快速抖动"
- HAL 版：PC13 LED 以约 5Hz 频率闪烁（亮约 100ms、灭约 100ms），肉眼能清晰看到闪烁

**通信异常时（ID 不是 `0x68`）**：

- 寄存器版：PC13 LED 以约 10Hz 频率较慢闪烁（亮约 50ms、灭约 50ms）
- HAL 版：PC13 LED 以约 1Hz 频率慢闪（亮约 500ms、灭约 500ms）

**程序卡死时**：LED 完全不闪，可能卡在寄存器版等待 I2C 标志（SB/ADDR/TXE/BTF/RXNE）的位置，或者 HAL 版 `error_handler()` 被触发（可通过 LED 是否亮来区分——error_handler 禁用中断后死循环，LED 保持进入时的状态）。

## 13. 常见问题排查

### 13.1 LED 慢闪

说明读到的 ID 不是 `0x68`。检查地址、AD0、供电、GND、PB6/PB7、上拉。

### 13.2 程序卡在等待 `ADDR`

地址阶段无 ACK。优先查模块是否在线、地址是否应为 `0x68` 或 `0x69`。

### 13.3 读到 `0x00` 或 `0xFF`

常见于 SDA/SCL 接线、上拉、电平或读流程异常。用逻辑分析仪看是否真的收到 ACK 和数据字节。

### 13.4 HAL 版没有明显错误但 ID 不对

给 `HAL_I2C_Mem_Write()` 和 `HAL_I2C_Mem_Read()` 加返回值判断，并在失败时点亮 LED 或断点查看 `hi2c1.ErrorCode`。

如果返回值是 `HAL_TIMEOUT`，多半是总线或从机响应问题；如果是 `HAL_ERROR`，再看 `hi2c1.ErrorCode` 判断是否 AF 应答失败、总线错误或仲裁相关错误。不要只看 `id`，因为 `id` 是结果变量，不是通信过程证据。

另外确认 HAL 地址参数是否用左移后的 `0xD0`。不同资料有的写 7 位地址 `0x68`，有的写 8 位地址 `0xD0`，移植代码时最容易在这里错一位。

### 13.5 后续读传感器数据不变化

确认已经写 `PWR_MGMT_1=0x00` 唤醒。身份寄存器能读到，不代表采样配置已经完整。

## 14. 本课最核心的结论

1. 访问 I2C 传感器要区分器件地址和内部寄存器地址。
2. MPU6050 常见 7 位地址是 `0x68`，写地址字节是 `0xD0`，读地址字节是 `0xD1`。
3. `WHO_AM_I` 是验证通信链路的优先寄存器。
4. `PWR_MGMT_1=0x00` 用于唤醒传感器。
5. 读寄存器需要先写寄存器地址，再重复起始读数据。
6. HAL 的 `Mem_Read/Mem_Write` 封装了寄存器访问流程，但地址长度和设备地址仍要自己填对。

## 15. 建议你现在怎么读这节课

先把 `0x68/0xD0/0xD1/0x6B/0x75` 五个值分清楚。再对照寄存器版读写函数，看“器件地址”和“寄存器地址”分别在哪一步发送。最后读 HAL 版，确认每个参数对应哪一层含义。

## 16. 扩展练习

1. 给 HAL 版补充返回值检查和错误闪烁模式。
2. 将 AD0 接高，把地址改为 `0x69` 验证地址变化。
