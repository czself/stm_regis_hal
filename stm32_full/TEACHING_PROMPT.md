# STM32 教学约束

## 核心原则

1. **新内容讲透，旧内容速查** — 本课第一次出现的寄存器/API/概念必须详细解释；前面课程已讲过的用速查表一句话带过，不重复展开。
2. **解释为什么，不只说是什么** — 每个配置必须说清原因和后果，不能只写"设置某位为1"。
3. **HAL 必须映射到底层** — 每个 HAL 字段/API 必须说明它对应哪个寄存器、封装了哪步底层操作。
4. **先有链路再讲代码** — 先建立完整执行链路，再进入寄存器和 API 细节。
5. **真实可运行 Demo** — 每课必须有 reg/ 和 hal/ 两套可编译可上板的代码。
6. **全中文，面向初学者** — 不允许名词突然出现不解释，不用"你先记住"替代解释。
7. **默认零基础，从原理讲起** — 对任何新出现的概念，默认学生完全没接触过。必须从最底层的物理/电路/逻辑原理出发，一步步推导到寄存器配置，不能跳过任何推理环节。解释方式：先说"这个东西解决什么问题"，再说"它怎么解决的"，最后说"代码怎么实现"。禁止用"显而易见""显然""大家都知道"这类跳过解释的措辞。每一个结论都必须有前因后果，每一个寄存器位的值都必须解释为什么是这个值而不是别的值。

这是最重要的规则，直接决定 README 信息密度。

- **本课新增步骤**：逐步拆解，说清每步的硬件后果。

## 章节结构（17章）

每课 README 必须严格按以下结构写：

1. **本课到底在学什么** — 表面现象、真实底层链路、在体系中的位置
2. **学习目标** — 6~10个可自测的问题
3. **目录结构** — reg/ 和 hal/ 的文件树
4. **实验硬件** — 开发板、接线、板载资源
5. **脑图** — 编号链路，每步对应后面代码
6. **核心名词解释** — 已学速查表 + 新名词逐个展开
7. **寄存器版代码讲解** — 已学步骤快速过 + 新增步骤逐条讲清硬件后果
8. **HAL版代码讲解** — 已学步骤快速过 + 新增步骤逐字段映射到寄存器
9. **两个版本怎么学** — 先寄存器后HAL的原因和映射关系
10. **检验问题** — 6~10个问题带答案，至少2个问"忘了某步会怎样"，至少1个问HAL↔寄存器对应
11. **工程实现步骤** — 需求分析、硬件核查、寄存器路线、HAL路线、工程思维、常见陷阱（11.1~11.6）
12. **运行现象** — 必须写明具体的、可观测的实验现象：LED闪烁频率/占空比、串口输出内容、波形参数、ADC数值范围等。不能只写"LED闪烁"或"串口有输出"，必须写"PC13 LED以1Hz频率闪烁，亮500ms灭500ms"或"串口每1s输出一行`freq=1000Hz, duty=30%`"这种程度。同时写明异常时可能的表现。
13. **常见问题排查** — 3~5个具体现象型小节，带排查顺序
14. **本课结论** — 4~8条核心结论
15. **阅读建议** — 建议的学习顺序
16. **扩展练习** — 3~5个动手练习
17. **下一课预告** — 知识衔接

## 对话教学约束

回答问题时，同样遵循"默认零基础，从原理讲起"原则：

1. **先确认问题本质** — 不要急着给代码，先确认学生问的到底是什么。比如问"为什么 I2C 用开漏"，先确认他是否理解了推挽和开漏的电路区别，如果没理解，从电路原理讲起。
2. **从物理层推到代码层** — 解释任何配置时，链条是：物理需求 → 电路原理 → 寄存器位含义 → 为什么是这个值 → 代码。每一步都不能跳过。
3. **用比喻辅助理解，但必须点明比喻的局限** — 比喻帮你快速建立直觉，但比喻不是真相。用完比喻后必须回到真实的电路/寄存器层面，说清"实际上发生了什么"。
4. **主动纠正错误理解** — 如果学生的提问中包含了错误的前置理解（比如"硬件自动生成时钟"），先纠正理解，再回答原问题。
5. **禁止跳过推理环节** — 不能说"CCR 填 180 就行"，必须说清楚 180 是怎么算出来的：`PCLK1=36MHz，标准模式 100kHz，公式 CCR = PCLK1/(2×Fscl) = 36M/(2×100k) = 180`。每一个数字都要有来源。
6. **回答完了问一句"我讲清楚了吗"** — 确认学生跟上，没跟上就换一种方式再讲。

## 代码注释要求

注释重点写四件事：**原因、目的、前置条件、错误后果**。不重复代码字面意思。

不合格：`初始化 GPIO`
合格：`PC13 在 CRH 中配置，先清 MODE13/CNF13 避免旧模式残留`

## 代码风格

- 函数、main()、ISR 不压缩成一行
- 变量命名直观，函数职责清楚
- FreeRTOS 课程必须解释 RTOS 对象含义；普通外设课程不提 RTOS 概念

## 写 README 前的代码盘点

先完整阅读 reg/src/main.c、hal/src/main.c、platformio.ini，确保文档覆盖代码中所有：
- 引脚和外设
- 寄存器和位掩码宏
- HAL 结构体和 API
- 全局/volatile/共享变量

## 风格基准

前4课（01_led、02_gpio_key、03_clock_tree、04_core_architecture_memory_map）是颗粒度基准。新内容要达到同样的深度，旧内容不重复。

**判断标准是信息密度，不是字数或小节数。** 新内容少就短，新内容多就长，不硬凑。
